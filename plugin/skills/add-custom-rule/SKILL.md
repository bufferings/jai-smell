# jai-smell のルールの登録

検出する表現のルールを、`~/.config/jai-smell/custom-rules.toml` に登録する。形態素の条件は、推測で記述せず、`jai-smell` コマンドの実行結果で確認する。IPADIC の分割結果は、語の見た目から予想した結果と異なる場合があるためである（「正典」は接頭詞「正」と名詞「典」に分割される）。

## 前提

- `jai-smell` コマンドが PATH に存在すること。存在しない場合は、インストールが必要であることを利用者に伝えて終了する。
- `~/.config/jai-smell/custom-rules.toml` が存在すること。存在しない場合は、`jai-smell init` の実行を利用者に依頼する。
- 特定のプロジェクトにのみ適用するルールは、そのプロジェクトの `jai-smell.toml` の `rule_sets` に登録する。登録先が依頼から判断できない場合は、`custom-rules.toml` に登録する。
- プリセットは `jai-smell` のバイナリに含まれるため、変更できない。プリセットの内容は、`jai-smell preset` で出力できる。

## 手順

検証用のファイルは、`mktemp -d` で作成した一時ディレクトリに配置し、登録の完了後に削除する。

### 1. 例文を用意する

次の 2 種類の例文を、それぞれ別のプレーンテキストのファイル（`.txt`）に、1 行に 1 文で記述する。

- 検出すべき例文（`positive.txt`）: 対象の表現を含む文。活用する語は、複数の活用形（終止形、連用形、未然形、「〜て」の形）を含める。利用者が示した文がある場合は、その文を含める。
- 検出してはならない例文（`negative.txt`）: 同じ語を別の意味で用いる文と、対象の語を一部に含む別の語の文。たとえば、「引く」を「〜から取得する」の意味で検出する場合は、「下線を引く」を含める。「走る」を検出する場合は、「自走する」を含める。

対象の表現が、どの文脈でも検出してよいものか、特定の文脈に限って検出するものかを、例文で確定する。判断できない場合は、利用者に確認する。

### 2. 登録済みのルールとの重複を確認する

プリセットと登録済みのルールのみを適用する設定ファイル（`current.toml`）を作成し、検出すべき例文をチェックする。プリセットは、設定ファイルに記述しなくても適用される。`--config` を指定すると、指定した設定ファイルのみが読み込まれるため、利用者の他の設定（textlint のルールなど）は結果に含まれない。

```toml
rule_files = ["~/.config/jai-smell/custom-rules.toml"]
```

```sh
jai-smell --config current.toml positive.txt
```

- 対象の表現の位置で検出された場合は、すでに登録されている。登録せず、検出したルールのメッセージを利用者に報告する。
- 一部の例文のみが検出された場合は、登録済みのルールの条件と、検出されなかった例文との差を報告し、登録するルールの範囲を利用者に確認する。

### 3. 形態素の分割を確認する

このスキルのディレクトリにある `probe.toml` を使用し、例文の分割位置と品詞を確認する。

```sh
jai-smell --config "${CLAUDE_SKILL_DIR}/probe.toml" positive.txt negative.txt
```

形態素ごとに `ファイル:行:列: 品詞` が出力される。列は、行の先頭からの文字数である。対象の表現が、いくつの形態素に、どの品詞で分割されるかを確認する。

### 4. 条件を記述して検証する

候補のルールのみを記述した設定ファイル（`candidate.toml`）を作成する。プリセットの検出結果を含めないように、`preset.enabled` に `false` を指定する。

```toml
[preset]
enabled = false

[[rule_sets]]
name = "検証"

[[rule_sets.entries]]
message = "検証"
tokens = [{ pos = "動詞", pos_detail_1 = "自立", basic_form = "叩く" }]
```

```sh
jai-smell --config candidate.toml positive.txt
jai-smell --config candidate.toml negative.txt
```

次の両方を満たすまで、条件を修正して再実行する。

- `positive.txt` のすべての行で、対象の表現の位置が検出される（終了コード 1）。
- `negative.txt` で 1 件も検出されない（終了コード 0）。

終了コード 2 は、設定ファイルの誤りを示す。エラーメッセージに従って修正する。

条件の記述の指針は次のとおりである。

- 条件に指定できるフィールドは、`surface_form`, `pos`, `pos_detail_1`, `pos_detail_2`, `pos_detail_3`, `conjugated_type`, `conjugated_form`, `basic_form`, `reading`, `pronunciation` である。値には、文字列または文字列の配列を指定する。
- 活用する語（動詞、形容詞）は、`basic_form` に基本形を指定する。すべての活用形が検出される。自立語のみを検出する場合は、`pos_detail_1 = "自立"` を指定する。
- 活用しない語（名詞など）は、`pos` と `surface_form` を指定する。
- `pos` を省略しない。省略すると、同じ表記の別の品詞の語も検出される。
- 別の意味の用法が検出される場合は、前後の形態素（格助詞、目的語の名詞）を条件の並びに追加する。
- `basic_form` で別の語の一部が検出される場合は、`surface_form` に活用形を配列で列挙する。
- 一致しない原因が特定できない場合は、条件のフィールドを 1 つずつ削除して再実行し、一致を妨げているフィールドを特定する。

検出してはならない例文を除外できる条件が存在しない場合は、誤検出が残る例文を利用者に示し、登録するかどうかを確認する。

### 5. 登録する

検証した条件を、`custom-rules.toml` に追加する。

- 分類が同じルールセットがすでに存在する場合は、そのルールセットの `entries` に追加する。存在しない場合は、ルールセットを新規に作成する。ルールセットの `name` は、検出する表現の分類を示す名前とする（「表記の統一」「社内で使用しない用語」）。
- `message` は、検出時に Claude への修正の指示として出力される。対象の表現、検出する理由、言い換えの例を、この順に記述する。言い換えの例は、利用者が示した表現を使用する。示されていない場合は、利用者に確認する。

  ```toml
  message = "\"サーバ\" は、表記を統一するため、「サーバー」と記述してください。"
  ```

- 前後の形態素を条件に含めた場合や、活用形を列挙した場合は、その条件が必要な理由を、`tokens` の直前のコメントに記述する。

  ```toml
  # 「引く」のみを条件にすると「下線を引く」も検出されるため、直前の「から」を条件に含める
  ```

### 6. 登録後の動作を確認する

`--config` を指定せずに、利用者の設定で例文を再度チェックする。

```sh
jai-smell positive.txt
jai-smell negative.txt
```

- `positive.txt` のすべての行で、登録した `message` が出力されることを確認する。
- `negative.txt` で、登録した `message` が出力されないことを確認する。他のルールの検出は、今回の登録とは関係がないため、対象外とする。
- 登録した `message` が出力されない場合は、`jai-smell config positive.txt` を実行し、`custom-rules.toml` が読み込まれていることを確認する。読み込まれていない場合は、`~/.config/jai-smell/jai-smell.toml` の `rule_files` に `custom-rules.toml` が指定されていることを確認する。

確認後に一時ディレクトリを削除し、登録したルール、検証に使用した例文、検出されない用法（検出してはならない例文として確認したもの）を利用者に報告する。
