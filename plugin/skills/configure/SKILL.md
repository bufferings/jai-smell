# jai-smell の設定

jai-smell の設定ファイル（`jai-smell.toml`）を作成または変更する。検出する内容の一覧を、現在の設定とあわせて利用者に提示し、利用者が選択した項目から設定ファイルを作成する。作成後に、利用者の文書を `jai-smell` コマンドでチェックし、検出件数を提示して調整する。検出が多すぎる設定は使用されなくなるため、利用者が許容できる件数にすることを優先する。

## 前提

- `jai-smell` コマンドが PATH に存在すること。存在しない場合は、インストールが必要であることを利用者に伝えて終了する。
- 設定ファイルが無い場合も、jai-smell は組み込みのデフォルトで動作する。利用者の選択がデフォルトと同じ場合は、設定ファイルを作成しない。
- 検出する表現の追加は、このスキルの対象外である。スキル `add-custom-rule` を使用する。

## 利用者への説明の方法

- 利用者は、ルールの名前を知らない前提で説明する。名前だけで説明せず、検出する内容と例を示す。「3 つのルール」のように、内容を示さずに数だけで言及しない。
- jai-smell のバージョン、過去のバージョンのデフォルト、変更の経緯には言及しない。利用者が判断に使用するのは、現在の動作と、選択した結果の動作だけである。既存の設定ファイルを読み込めない場合（手順 1）は例外で、設定ファイルの修正が必要であることを説明する。

## 検出する内容の一覧

利用者に提示する一覧の内容である。表現のルール、textlint のルールの 3 つの分類、Claude の返答のチェックに分かれており、分類ごとに提示する。「デフォルト」は、設定ファイルが無い場合の動作を示す。

「推奨」の ○ は、検出を推奨する項目を示す。推奨の基準は、誤りである可能性が高い記述を検出することと、問題のない記述を検出する件数が少ないことである。○ の無い項目は、文体や表記の方針によって要否が異なる項目と、技術文書で一般的な記述も検出する項目である。次の場合は、○ の無い項目もあわせて提案する。

- 硬い文体に統一する文書（仕様書、公式のドキュメント）: `colloquial`
- AI が生成した文章を主な対象とする場合: 「AI が生成した文章に多い記述」の残りの項目

### 表現のルール

jai-smell が提供する、表現のルールである。個別の表現は、`jai-smell expressions` で出力できる。

| 設定の名前 | 検出する内容と例 | デフォルト | 推奨 |
| --- | --- | --- | --- |
| `translationese`（不自然な日本語化） | 英語の表現を日本語に置き換えた不自然な表現。「CI が走る」→「実行される」、「既定では」→「デフォルトでは」 | 検出する | ○ |
| `metaphor`（比喩） | 物事を別のものにたとえた表現。「落とし穴」→「注意点」、「土台」→「基盤」 | 検出する | ○ |
| `unusual-terms`（技術文書で一般的ではない用語） | 他の分野の用語。「地の文」→「本文」 | 検出する | ○ |
| `colloquial`（話し言葉） | 文書では用いない話し言葉。「使う」→「使用する」、「見る」→「確認する」。使用頻度の高い言葉が対象のため、件数が多くなる | 検出しない |  |
| `prefer-hiragana`（漢字をひらく） | ひらがなで記述する表記。「無い」→「ない」 | 検出しない |  |

### textlint のルール（文の構成と表現）

デフォルトでは、すべて検出しない。

| 設定の名前 | 検出する内容 | 推奨 |
| --- | --- | --- |
| `sentence-length` | 1 文が 100 文字を超える |  |
| `max-ten` | 1 文の読点（、）が 3 つを超える | ○ |
| `max-comma` | 1 文のカンマ（,）が 3 つを超える | ○ |
| `max-kanji-continuous-len` | 漢字が 6 文字を超えて連続する |  |
| `no-doubled-joshi` | 1 文の中で同じ助詞が連続する（「〜の〜の〜の」） | ○ |
| `no-doubled-conjunction` | 同じ接続詞が連続する（「しかし、〜。しかし、〜。」） | ○ |
| `no-doubled-conjunctive-particle-ga` | 1 文の中で逆接の「が」が連続する | ○ |
| `no-double-negative-ja` | 二重否定（「〜ないわけではない」） | ○ |
| `no-dropping-the-ra` | ら抜き言葉（「見れる」） | ○ |
| `ja-no-redundant-expression` | 冗長な表現（「することができます」） | ○ |
| `ja-no-weak-phrase` | 弱い表現（「〜かもしれない」「〜と思います」） |  |
| `ja-no-successive-word` | 同じ単語の連続（「これはは」） | ○ |
| `ja-no-abusage` | よくある誤用（「適用」と「適応」の混同など） | ○ |
| `ja-no-mixed-period` | 文末に句点（。）が無い。ソースコードのコメントには、この項目を選択した場合にのみ適用される |  |
| `no-mix-dearu-desumasu` | 「である」調と「ですます」調の混在 | ○ |

### textlint のルール（文字と記号）

デフォルトでは、すべて検出しない。

| 設定の名前 | 検出する内容 | 推奨 |
| --- | --- | --- |
| `no-exclamation-question-mark` | 感嘆符と疑問符（！？） |  |
| `arabic-kanji-numbers` | 算用数字と漢数字の使い分け（「1つ」と「一つ」） |  |
| `ja-unnatural-alphabet` | 日本語の中の不自然なアルファベット（入力の誤り） | ○ |
| `no-unmatched-pair` | 対応していない括弧 |  |
| `no-hankaku-kana` | 半角カタカナ | ○ |
| `no-nfd` | 濁点と半濁点が分離した文字 | ○ |
| `no-invalid-control-character` | 不要な制御文字 | ○ |
| `no-zero-width-spaces` | ゼロ幅スペース | ○ |

### textlint のルール（AI が生成した文章に多い記述）

デフォルトでは、すべて検出しない。

| 設定の名前 | 検出する内容 | 推奨 |
| --- | --- | --- |
| `no-ai-list-formatting` | `- **項目**: 説明` の形式のリスト項目、絵文字で始まるリスト項目 |  |
| `no-ai-emphasis-patterns` | 太字の接頭辞（`- **例**`）、見出しの中の太字 |  |
| `no-ai-hype-expressions` | 誇張表現（「革命的な」「究極の」「完全に」「大幅に」）。「完全に削除する」のような事実の記述も検出する | ○ |
| `no-ai-colon-continuation` | コードブロックやリストの前の、コロンで終わる文 |  |
| `ai-tech-writing-guideline` | 「する必要があります」などの冗長な表現、「適切な」「必要に応じて」などの曖昧な表現、「〜が行われます」などの受動的な表現 | ○ |

### Claude の返答のチェック

Claude Code が返答を終了した時点で、返答の本文をチェックする。検出した場合は、Claude に再出力を指示する。デフォルトでは適用しない。

| 設定のキー | 内容 | 推奨 |
| --- | --- | --- |
| `japanese` | 大部分が英語の返答を検出し、日本語での再出力を指示する。日本語の文に英字の用語が含まれる返答と、コードだけの返答は対象外 | ○ |

利用者には、次の動作をあわせて説明する。

- チェックは、返答が画面に表示された後に実行される。検出した場合は、元の返答、再出力の指示、再出力した返答の順に表示される。
- 再出力した返答は、再度チェックしない。1 回の返答で、再出力は 1 回までである。
- 再出力は、大部分が英語の返答の場合にだけ発生する。

## 適用される範囲

表現のルールと textlint のルールでは、適用される範囲が異なる。利用者には、項目の選択を依頼する前に、次の要約を説明する。

| 種類 | 適用される範囲（デフォルト） |
| --- | --- |
| 表現のルール | すべてのファイルの、文章の部分。ソースコードでは、コメントと文字列だけが対象で、コードは対象外 |
| textlint のルール | `.md` と `.txt` の本文。ソースコードは、対象のファイルに指定した場合に、コメントだけが対象になる |

違いの理由は、ルールの性質である。表現のルールは、特定の言葉との一致で検出するため、文章ではない部分で誤って検出する可能性が低い。textlint のルールは、対象が文章であることを前提としており（1 文の長さ、文末の句点など）、文章ではない部分に適用すると誤検出が多くなる。

対象のファイルは、`[expressions]` と `[textlint]` の `include` と `exclude` で、それぞれ変更できる。

次の表は、ファイルの種類ごとの詳細である。利用者が特定の種類のファイルの扱いを質問した場合にだけ使用し、通常の説明では提示しない。項目の選択の判断に必要な内容は、上の要約に含まれているためである。

| ファイルの種類 | 表現のルール | textlint のルール |
| --- | --- | --- |
| Markdown | 本文。コードブロック、インラインコード、URL は対象外 | 表現のルールと同じ |
| ソースコード | コメントと文字列リテラル | コメントのみ。対象のファイルに指定した場合に適用される |
| その他のテキスト（`.txt`、`.yml`、`.json` など） | ファイル全体 | `.txt` はファイル全体。その他は、対象のファイルに指定した場合に適用される |
| 言語を判定できないファイル | ファイル全体 | 適用されない |

## 設定の仕様

設定ファイルは 2 種類ある。両方が存在する場合は統合され、チェック対象のファイルに近い設定ファイルの指定が優先される。

| 種類 | 場所 | 相対パスの glob の基準 |
| --- | --- | --- |
| ユーザー全体の設定 | `~/.config/jai-smell/jai-smell.toml` | `/` |
| プロジェクトの設定 | リポジトリのルート、またはその下位のディレクトリの `jai-smell.toml` | その設定ファイルのディレクトリ |

記述できる内容は次のとおりである。

```toml
# チェックの対象外とするファイル。すべてのチェックに適用される
exclude = ["**/CHANGELOG.md"]

[expressions]
# false を指定すると、表現のルールを適用しない
enabled = true
# 表現のルールを適用するファイル。省略した場合は、すべてのファイルに適用する
include = ["**/*.md"]

[expressions.rules]
# colloquial と prefer-hiragana は、true を指定した場合にのみ適用する
colloquial = true
prefer-hiragana = true
# その他のルールは、false を指定すると適用しない
metaphor = false

[textlint]
# true を指定すると、textlint のルールを適用する
enabled = true
# 省略した場合は、.md と .txt に適用する。ソースコードを指定した場合は、コメントに適用する
include = ["**/*.md", "**/*.txt", "**/*.ts"]

[textlint.rules]
# false は無効、true はルールのデフォルトのオプション、テーブルはオプションの指定
sentence-length = { max = 120 }
no-exclamation-question-mark = false
no-ai-list-formatting = true

[replies]
# true を指定すると、大部分が英語の返答を検出する
japanese = true
```

`textlint.enabled = true` を指定した場合の、ルールごとのデフォルトは次のとおりである。

- 「文の構成と表現」と「文字と記号」のルールは、`no-mix-dearu-desumasu` を除いて適用される。適用しないルールには `false` を指定する。
- `no-mix-dearu-desumasu` と「AI が生成した文章に多い記述」のルールは、適用されない。適用するルールには `true` を指定する。
- `no-mix-dearu-desumasu = true` は、見出し、本文、箇条書きのそれぞれで、多いほうの文体と異なる文を検出する。文体が統一されている文書は検出しない。利用者が文体の固定（例: 箇条書きは「である」調）を依頼した場合にだけ、オプションで指定する（`{ preferInBody = "ですます", preferInList = "である" }`）。文体の固定は、利用者に質問しない。

表現のルールの調整は、一覧の項目の単位である。項目の中の特定の表現だけを対象外にする設定は無い。特定の箇所を対象外にする場合は、ファイルに除外のコメント（`jai-smell-disable-next-line 表現`）を記述する。

## 手順

### 1. 現在の設定を確認する

利用者がチェックしたい文書を 1 つ選び、現在適用されている設定を確認する。文書が特定できない場合は、現在のディレクトリの `README.md` などを使用する。

```sh
jai-smell config README.md
```

読み込まれた設定ファイルと、適用される表現のルール、textlint のルールが出力される。既存の設定ファイルがある場合は、内容も読む。

コマンドがエラーを出力した場合は、既存の設定ファイルを読み込めていない。この状態では、ファイルの編集のチェックも実行されていない。項目の質問に進む前に、次の順序で対応する。

1. 利用者に、設定ファイルを読み込めないこと、チェックが実行されていないこと、エラーメッセージの内容を伝える。
2. 修正の内容を提示し、修正してよいかを確認する。修正の前に、一時ディレクトリ（`mktemp -d`）にコピーを保存する。
3. 修正の後に、コマンドを再度実行し、エラーが出力されないことを確認する。

`[preset]` を記述した設定ファイルは、次のように修正する。

| 修正前 | 修正後 |
| --- | --- |
| `[preset]`（`enabled`、`include`、`exclude`） | `[expressions]`（キーは同じ） |
| `[preset.rule_sets]` | `[expressions.rules]` |
| `"不自然な日本語化"` | `translationese` |
| `"比喩"` | `metaphor` |
| `"技術文書で一般的ではない用語"` | `unusual-terms` |
| `"話し言葉"` | `colloquial` |
| `"漢字をひらく"` | `prefer-hiragana` |

修正前の設定ファイルに `"話し言葉"` と `"漢字をひらく"` の記述が無い場合、修正前はこの 2 つが適用されていた。`colloquial` と `prefer-hiragana` は、`true` を指定した場合にのみ適用されるため、継続して適用するかどうかを利用者に質問する。

`claude` コマンドでスキルを使用できているが、`jai-smell config` の出力に「Claude の返答のチェック」が含まれない場合は、`jai-smell` コマンドがプラグインより古い。`brew upgrade jai-smell` の実行を利用者に依頼する。

### 2. 設定ファイルの場所を質問する

- ユーザー全体の設定: すべてのプロジェクトに適用する。
- プロジェクトの設定: 現在のリポジトリにのみ適用する。チームで共有するリポジトリでは、設定ファイルをコミットするかどうかを利用者に確認する。

依頼の内容から判断できる場合は、質問しない。選択肢を提示するツールを使用できる場合は、そのツールを使用する。

### 3. 表現のルールを質問する

次の順序で進める。適用される範囲を先に説明し、利用者が「どこに適用されるルールか」を把握したうえで項目を選択できるようにする。

1. 適用される範囲を説明する。「適用される範囲」の要約の、表現のルールの内容を 1〜2 文で説明する。
2. 「検出する内容の一覧」の表現のルールを提示し、検出する項目の選択を依頼する。
3. 対象のファイルを質問する。すべてのファイルのままとするか、特定の種類のファイル（`.md` のみなど）に限定するかである。選択肢を提示するツールを使用できる場合は、そのツールを使用する。

### 4. textlint のルールを質問する

次の順序で進める。

1. 適用される範囲を説明する。「適用される範囲」の要約の、textlint のルールの内容を 1〜2 文で説明し、表現のルールとの違いと、その理由を説明する。
2. 「検出する内容の一覧」の textlint のルールを、次の 3 つの分類の順に、1 回に 1 つの分類だけ提示して、検出する項目の選択を依頼する。利用者の回答を受けてから、次の分類に進む。
   - 文の構成と表現
   - 文字と記号
   - AI が生成した文章に多い記述
3. 1 つ以上選択した場合は、対象のファイルを質問する。`.md` と `.txt` のみか、ソースコードのコメントも含めるかである。含める場合は、リポジトリで使用している言語の拡張子を `include` に指定する。

### 5. Claude の返答のチェックを質問する

「検出する内容の一覧」の Claude の返答のチェックを、内容と動作の説明とあわせて提示し、適用するかどうかを質問する。`japanese` には「（推奨）」を付ける。選択肢を提示するツールを使用できる場合は、そのツールを使用する。

返答のチェックの設定は、作業ディレクトリに適用される設定ファイルから読み込まれる。すべてのプロジェクトに適用する場合は、ユーザー全体の設定に記述する。

### 一覧の提示と回答の方法

手順 3 と 4 で一覧を提示する際は、次の方法に従う。

項目には、分類の中での番号と、現在の設定での状態を付ける。現在検出している項目には `[x]` を、検出していない項目には `[ ]` を付ける。検出する内容と例を省略しない。

```
textlint のルール（文の構成と表現）
[ ]  1. sentence-length: 1 文が 100 文字を超える
[ ]  2. max-ten: 1 文の読点（、）が 3 つを超える（推奨）
…
```

推奨の項目には、行の末尾に「（推奨）」を付ける。一覧の前に、推奨の基準を 1 文で説明する。

利用者には、状態を変更する項目の番号を回答するよう依頼する。回答した番号の項目は、検出していない項目（`[ ]`）であれば検出する設定に、検出している項目（`[x]`）であれば検出しない設定に変更する。「検出する項目を回答する」という依頼にしない。検出している項目としていない項目が混在する一覧では、回答が「追加する項目」と「検出する項目のすべて」のどちらにも解釈できるためである。

次の指定方法を示す。

- 番号を列挙する（「4、5 を検出する」「2 を検出しない」）
- 推奨のとおりにする（「推奨のとおり」「推奨のとおり。加えて 1 も検出する」）。推奨の項目を検出し、その他の項目を検出しない設定にする
- すべてを指定する（「すべて検出する」「すべて検出する。ただし 11 は除く」）
- 変更しない場合は、その旨を回答する

回答の解釈が複数ある場合は、次の分類に進む前に確認する。

分類の項目数は、選択肢を提示するツールの上限を超えるため、項目の選択は文章で提示し、文章での回答を依頼する。

依頼の内容から変更したい分類が判断できる場合は、その分類だけを質問する。

すべての回答が完了した後に、検出する項目と、それぞれの対象のファイルをまとめた一覧を提示し、内容が利用者の意図と一致していることを確認する。

選択の結果がデフォルトと同じで、既存の設定ファイルも無い場合は、設定ファイルが不要であることを伝えて終了する。

### 6. 設定ファイルを作成する

選択の結果に基づいて、設定ファイルを作成または変更する。

- 表現のルール: デフォルトと異なる項目だけを `[expressions.rules]` に記述する。
- textlint のルール: 1 つ以上選択した場合は、`[textlint]` に `enabled = true` を記述する。`[textlint.rules]` には、「設定の仕様」のルールごとのデフォルトと異なる項目だけを記述する。1 つも選択していない場合は、`[textlint]` を記述しない。
- Claude の返答のチェック: 適用する場合にだけ、`[replies]` に `japanese = true` を記述する。
- 既存の設定ファイルを変更する場合は、変更の前に、一時ディレクトリ（`mktemp -d`）にコピーを保存する。利用者の記述（`rule_files`、`rule_sets`、コメント）は保持し、選択に関係するキーだけを変更する。
- 設定ファイルが存在しない場合は、必要な内容だけを記述したファイルを作成する。ユーザー全体の設定は、`~/.config/jai-smell/` が存在しない場合はディレクトリも作成する。

作成後に、手順 1 と同じコマンドで、適用される内容が選択の結果と一致していることを確認する。設定ファイルに誤りがある場合は、エラーメッセージが出力される。エラーメッセージに従って修正する。

### 7. 利用者の文書で検出件数を確認する

利用者の文書を数件チェックし、検出件数を集計する。対象は、利用者が日常的に編集する文書とする。文書が多い場合は、5 件程度に限定する。

```sh
jai-smell docs/*.md > findings.txt
# textlint のルール別の件数
grep -o '（textlint: [a-z-]*）$' findings.txt | sort | uniq -c | sort -rn
# 表現のルールの表現別の件数
grep -v '（textlint: ' findings.txt | sed -E 's/^.*:[0-9]+:[0-9]+: ("[^"]*").*/\1/' | sort | uniq -c | sort -rn | head -20
```

`findings.txt` は、一時ディレクトリに作成する。終了コード 1 は検出があったことを、終了コード 2 は設定ファイルの誤りを示す。

利用者に、検出の総数、件数の多い項目、検出された文の例を 2〜3 件提示する。フックは編集した部分だけをチェックするため、既存の文書の検出がすべて一度に報告されるわけではないことも伝える。

### 8. 調整する

件数の多い項目について、利用者に対応を質問する。

- 項目を検出しない設定にする: 項目の名前を示して、判断を依頼する。
- textlint のルールの条件を変更する: オプションを指定する（`sentence-length = { max = 120 }`、`no-ai-hype-expressions = { allows = ["完全に"] }`）。
- 特定のファイルを対象外にする: `exclude` に追加する。自動生成される文書、変更履歴、他者の文章の引用を含む文書が該当する。
- 特定の種類のファイルにのみ適用する: `[expressions]` または `[textlint]` の `include` を指定する。

表現のルールは、項目の中の特定の表現だけを対象外にする設定が無いため、項目の単位で判断を依頼する。

設定を変更した場合は、手順 7 を再度実行し、変更の前後の件数を提示する。利用者が件数を許容するまで繰り返す。

### 9. 完了を報告する

次の内容を報告し、一時ディレクトリを削除する。

- 作成または変更した設定ファイルのパスと、設定の内容
- 検出する項目の一覧（最終の状態）と、それぞれが適用される範囲
- 調整の前後の検出件数
- 既存の設定ファイルを変更した場合は、変更した箇所

利用者が変更の取り消しを依頼した場合は、手順 6 で保存したコピーから復元する。
